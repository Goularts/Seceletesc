# Revisão da F0 (Fundação): disposição dos achados

Revisores: `seguranca` e `guardiao-regras` (coordenação via Ruflo), mais testes de mutação.
Resultado integrado: PR #2.

**Disposições possíveis:**

- **Corrigido**, com a evidência de como foi corrigido.
- **Aceito como risco**, com o motivo e onde está documentado.
- **Adiado**, com a fase em que será tratado.
- **Rejeitado**, com o motivo.

## Segurança

| # | Sev. | Achado | Disposição |
|---|---|---|---|
| S1 | Alta | Migrador era superusuário: superusuário ignora RLS mesmo com FORCE | **Corrigido.** Papéis passam a ser criados por um script de provisionamento; migrações rodam como `seceletesc_dono`, sem superusuário. A migração recusa rodar com superusuário ou BYPASSRLS |
| S2 | Alta | Nenhum teste falharia se o `FORCE ROW LEVEL SECURITY` fosse removido | **Corrigido.** Testes com o dono não superusuário. Mutação: sem o FORCE, 2 testes falham |
| S3 | Média | Qualquer papel pode definir `app.tenant_id` na própria transação | **Aceito como risco.** É inerente ao desenho com RLS por variável de sessão. Mitigação: só a infraestrutura define o tenant; nenhum SQL vindo de entrada externa é executado. Documentado em plano-tecnico.md, seção 6 |
| S4 | Média | O dono consegue desligar trigger ou política (append-only não protege contra o dono) | **Aceito como risco.** É inerente a ser dono das tabelas. Mitigação: a aplicação nunca usa o dono; mudanças no banco só por migração com checksum. Documentado em plano-tecnico.md, seção 6 |
| S5 | Média | Trigger e falta de GRANT devolviam o mesmo código 42501, então o teste não distinguia um do outro | **Corrigido.** O trigger passa a usar o código P0001, e testes conferem os GRANTs com `has_table_privilege` |
| S6 | Média | Testes aceitavam qualquer `PostgresException` | **Corrigido.** Agora conferem o código exato: 42704 sem tenant, 22P02 depois de reutilizar a conexão |
| S7 | Média | Faltavam testes de grants: worker executando o resolvedor, app gravando no mapeamento, papéis donos ou com BYPASSRLS | **Corrigido.** 2 testes novos, um deles parametrizado |
| S8 | Baixa | O papel app pode descobrir qual tenant usa um `phone_number_id` testando valores | **Aceito como risco** (baixo: só serve a quem já recebe o webhook). Documentado em plano-tecnico.md, seção 6 |
| S9 | Baixa | Migrador sem `search_path` fixo e sem checksum | **Corrigido.** `search_path` fixo e SHA-256 por migração, com quebra de linha normalizada |
| S10 | Baixa | INSERT permitia escolher id (`OVERRIDING SYSTEM VALUE`) e horário retroativo | **Corrigido.** Trigger carimba id e horário; teste novo |
| S11 | Baixa | Imagens fixadas só por tag; pacotes NuGet sem lock file | **Corrigido.** Imagens por digest; `packages.lock.json` e `--locked-mode` no CI |
| S12 | Baixa | Senha padrão no compose | **Aceito.** Vale só para o container local, que escuta apenas em 127.0.0.1 |
